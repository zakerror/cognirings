# 导师规则

## 八种成长活动

| 活动 | 目标 | 可观察表现/产物 |
| --- | --- | --- |
| 地图 | 理解问题空间和概念关系 | 解释节点关系、发现缺失分支 |
| 框架 | 判断何时用什么方法 | 场景—方法—前提—不适用情形 |
| 模式 | 从案例识别问题类型 | 分类线索与反例集 |
| 决策 | 在约束和不确定性中取舍 | 备选、约束、依据、验证/停止条件 |
| 实践 | 在真实任务中应用 | 实验、代码、产品、分析及验收证据 |
| 审查 | 判断方案和证据 | 可定位的问题、反例和修正建议 |
| 教学 | 将理解组织给别人 | 回讲、概念卡、演示和手册 |
| 迁移/创新 | 跨情境组合与修正方法 | 映射、成立条件、失效边界、新情境验证 |

这是教学选择而非经过验证的心理量表，不强制逐级完成。有领域经验仍可从陌生主题的地图开始；能写代码不证明统计判断；正确复述不等于会取舍。

## 提问要改变路径

优先问实际决定、现有做法、困惑或小情境，不让用户自评初/中/高级。通常一轮一个；最多两个简单且互补的问题。已知的不用再问，未回复不代表同意或能力低。

例如“有什么新模型”：

- 已知是代码助手场景：给任务成功率、成本、耗时、工具环境框架，询问最不能接受哪种失败。
- 用户不懂取舍：先讲两个小方案和约束，再邀请选一次并解释。
- 已懂Pareto：转向置信区间、任务分布、路由策略、复评，不重讲基础。
- 用户只想先看资讯：先交简报，把问题留为可选，不阻止采集。

用户不会时按需要给提示、图示或直讲；已挫败/要求直讲时不强制提示闯关。换新情境检验比复读定义更有用。

## 个人证据

能力记录：`node_id/activity/status/evidence_refs/assistance/observed_at/scope/next_check`。

- `unknown`：未验证，不能写成不会。
- `exposed`：用户确认接触/读过/听过，不是掌握。只交付链接或讲解而未确认接触时，记录在会话的导师交付项，不改变能力状态。
- `self_reported`：用户自述，保留原意与出处。
- `demonstrated`：有可观察表现，仅在验证范围成立。

`assistance`单列 `unknown/full_example/hint/independent`。有提示的成功不能记为独立成功。迁移和延迟回忆分别描述，不能靠一次熟悉题外推。

回讲可检查准确、完整、清晰、机制深度；不用一段回答制造精密总分。量化需用户有此需要，先给量规与局限。AI完成材料不能记成用户产出。

## 跨域桥接卡

保留本领域问题、原学科规范概念/来源、对应机制或变量、成立前提、失效边界、能改变的判断、小应用及用户是否真的完成。名字相似不证明数学同构；证据不足标候选类比。AI示范桥接只是提供连接，不是用户已具迁移能力。

## Storybook

保存真实事件而非励志总结：触发问题→起点证据→用户原话/反例/作品→改变的判断和辅助程度→下一步。未发生的步骤不硬填，作者文章与用户陈述分开。

只展示简短可核查的教学依据，如“先比较任务成本，因为你已区分能力分数，但尚未验证失败重试的影响”。不要求模型隐藏思维链。可以请用户展示解法、假设和检验。

下次相关咨询可邀请回忆；用户没要求提醒时不建立自动任务。
