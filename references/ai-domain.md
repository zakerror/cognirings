# AI领域种子

提供四个可选入口，按用户的问题展开，不固定为所有人的课程。

| 分支 | 核心问题 | 节点 |
| --- | --- | --- |
| 模型与行业 | 能力/可获得性变了什么 | 能力边界、模态、开闭源、访问、版本/推理强度、基准适用性 |
| 应用工程 | 如何可靠转为生产力 | Agent运行环境、工具/MCP、上下文/记忆、工作流、多Agent、观测、审批、部署恢复 |
| 评测优化 | 如何证明变好、权衡投入 | 构念/效度/信度、任务分布、测试集、实验、效应量/不确定性、质量/成本/时延、路由/缓存/压缩 |
| 来源判断 | 什么值得看、何时相信 | 一手发布、独立评测、社区线索、方法透明、版本可比、利益与更新 |

## 候选跨域桥

- Judge漂移→测量论信度/评分者一致性；一致不保证效度。
- 评测提升→统计学效应量/置信区间/实验；显著不等于重要。
- 无法随机实验→因果推断；需识别假设，不能把相关写成因果。
- 质量/成本/耗时→运筹学多目标优化和决策理论。
- Agent闭环→控制论反馈/延迟/稳定性；说明类比差异。
- 可用性/尾延迟→排队论/可靠性工程；均值可能掩盖长尾失败。
- 解释与反例→教学/元认知；有材料不等于自己理解。

## 帕累托图的两种意思

多目标选型通常指Pareto前沿：同一可比任务/约束下，没有另一个方案在所有目标不差且至少一项更好。“主要问题/贡献在哪里”可能指80/20累计柱状图。按上下文暂定并说明，用户纠正则调整。

作图先固定任务/数据集、模型版本、Agent运行环境、推理预算、质量/成本/时延口径、时间与样本不确定性。不同评测/版本分数不能直接拼图，缺失值不补0。成本区分每token、每任务、每成功任务、含重试/工具/人工总成本。缺可比数值就给概念示意或待采字段，不造排行榜。

前沿不等于最适合用户，还需业务约束、可获得性、可靠性与维护成本；前沿可能随样本误差、时间和任务分布改变。

## 信息源

先用用户收藏，再补缺口。platform和publisher分开：GitHub是平台，组织是发布者。

- 官方发布/文档确认功能、版本和限制，性能结论仍需独立验证。
- GitHub release/源码确认实现变化，Star不是有效性证明。
- Artificial Analysis等评测对照质量/成本/速度，读方法与日期，不代替自己的工作负载。
- 论文/作者代码解释方法和假设，预印本不等于共识。
- 教材/大学课程补前置，标基础而非近期新闻。
- 社区/聚合站发现线索，再追源头。

近期报告以少量高价值事项为主，可搭配基础补课、跨域桥和小实践，不必每次填满四类或固定数量。
