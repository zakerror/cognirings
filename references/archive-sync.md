# 沉淀后同步个人档案

适用于用户明确要求一次同步，或已授权“以后每次沉淀后同步”的档案。通用技能保存引导方法和工具；目标仓库保存个人知识体系、认知画像、学习路径和历史，两者分别发布。遵循[档案契约](archive-contract.md)，不因同步重新初始化或推翻已符合契约的结构。

## 续接与授权配置

读取档案内`.cognirings/policies/publication.json`：保存仓库、分支、触发条件、授权范围和排除规则。本机源路径、检出路径和SSH alias映射保存在`.cognirings/sync.local.json`并加入发布副本的忽略列表；不存私钥、Cookie或token。

下面是配置形状；目标由用户的实际授权填写，不把示例当成授权：

```json
{
  "enabled": true,
  "trigger": "after_each_saved_activity",
  "repository": "https://github.com/OWNER/PERSONAL-ARCHIVE",
  "branch": "main",
  "authorization": "User explicitly authorized sync and push after each saved activity",
  "scope": ["knowledge", "profile", "journal", "required_portable_metadata"],
  "exclude": ["credentials", "private_paths", "internal_source_documents", "raw_runs", "drafts"]
}
```

已有授权涵盖同一目标和范围时直接执行，不重复要求确认。目标变化、超出范围的内容不从原授权推导。用户暂停或撤回时更新配置。没有授权时按本地档案处理；用户要求本次不记档时也不触发同步。

## 每次沉淀结束时

1. 完成正式纪事和当前知识/画像综合，刷新后验证源档案。先检查本机是否已有检出目录；检查工作区、远端URL和分支，fetch后审阅远端新增提交。已有远端改动应合并保留；不强推、不静默覆盖用户未提交修改。
2. 审查结构是否符合knowledge/profile镜像主题、journal唯一原文和维护区分离。可沿用就增量更新；确有结构调整时保留稳定ID、阅读链接和历史。迁移、同步不刷新知识日期、不提升理解等级。
3. 构建可发布副本，按明确清单同步当前阅读页、干净的新纪事、注册表、证据、政策和必要工具。默认排除`.cognirings/work/`、原始研究运行、运行时配置、缓存、本机同步配置和私密材料；需要的干净上下文单独审阅后纳入。不要用整目录覆盖或`rsync --delete`把本地私密/旧版目录复制上去，也不要删除未审阅的远端文件。
4. 已发布且冻结的历史可能是本地原件的脱敏投影。保留其原文与既有哈希，不能用本地版本直接覆盖。新纪事核验后按发布内容登记；注册表合并既有发布历史与新记录，不能用本地哈希覆盖发布副本的清单。可在维护清单记录源/发布文件哈希与排除范围，便于下次比较。若源历史发生实质变化，先按纠错/隐私删除规则处理，不用重建哈希掩盖修改。
5. 发布投影中的内部来源保留稳定ID、用途及访问说明；不恢复内部URL或复制内部原文。已有脱敏条目优先保留其公开字段；新条目无法安全投影时先排除并检查引用闭合。
6. 用发布副本的工具验证结构、冻结哈希、引用闭合和可携带链接；审阅暂存diff与范围，再提交、推送到配置分支。核对远端提交确实包含本次结果后，才报告同步成功。最后更新本地维护状态；该状态属于维护记录，不增加学习报告数量。

推送中遇到竞态拒绝时获取远端并合并审阅后重试；权限/网络受阻则保留已校验的本地成果，记录未同步内容和原因，明确告知用户。没有内容差异时报告已同步，不制造空提交。授权持续有效，但不会创建后台进程、定时器或自动同步其他无关仓库。

## 当前状态与发布副本

在本地和发布副本AGENTS中保留这条续接规则及配置入口。首页直接进入当前知识、画像、学习路径和最近正式报告；不让读者靠旧补充稿拼出当前结论。历史报告的原始研究日期保留，避免“本周”导读在后续月份被误读为实时资讯。

技能自身升级单独在技能仓库提交；个人档案配置和认知内容不回流通用技能仓库。同步并不代表重新核验了旧新闻，也不能使U或实践状态自动升级。
