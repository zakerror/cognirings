# 搜索兴趣、社区关注与个人阅读优先级

用于近期资讯检索、整理和推荐。执行前仍遵循[检索适配](research-adapter.md)；本文件定义核验后的上层补充，不替代或改写原版 last30days。规则版本：`cognirings-priority-v1.1.1`（沿用v1.1权重，增加模拟数据隔离）。

## 检索时怎样加入搜索热度

1. 从知识树与研究问题确定公开实体、产品/模型版本或研究主题，先排除歧义。保留事件与查询的映射理由，不把个人画像发给搜索引擎。
2. 在正常近期检索之外尝试 Google Trends：优先可访问的官方 Explore 页面和图表 CSV；已有 API 授权时可使用官方 API。需要中文搜索需求时，另外查看百度指数。不能只打开来源首页就写成“已取得热度”。
3. 在看指数之前确定地域、时间窗、搜索类型、类别、词/主题口径与候选比较集合。优先让待比较对象出现在同一请求/导出中；保留原始查询链接、采集时间和比较批次。检索结果中的总命中数、页面SEO排名、自动补全不当作搜索量。
4. 搜索上升可以引出待查线索，但必须回到原始公告、论文或代码核验。广义品牌热度可解释背景，不能归因到该品牌所有事件。比如“某公司”的搜索高峰不能直接给其多个版本更新和合作公告各加一次分。
5. 无法取得或比较的数据记录具体状态，继续其余来源的研究。无需为完成一次咨询申请 API、注册账户、购买指数服务或修改上游。用户已有授权按实际范围复用。

### 来源与实际访问方式

| 来源 | 取得方式 | 可解释什么与限制 |
| --- | --- | --- |
| Google Trends 网页 | 可访问的 Explore / Classic；图表 Download 的官方 CSV；用户已有导出 | 同一条件下的相对搜索兴趣，网页尺度0—100；每次请求独立缩放，不能跨独立批次直接比两个100 |
| Google Trends API | 已有、可用的官方授权 | 截至2026-11-06仍为申请制 Alpha；跨请求一致尺度，不是网页0—100，不能直接除100 |
| 百度指数 | 可访问的官方页面、用户提供数据或已有授权服务 | 中文搜索需求；保留PC/移动/整体、地区和时段。搜索指数与媒体/资讯指数不同，不互相替代 |
| 其他引擎数据 | 先核验提供方方法、范围和访问条件 | 仅接受真实、可追溯的需求指标；未建立可比尺度时单列背景，不能自动并入分数 |

依据：[Google数据FAQ](https://support.google.com/trends/answer/4365533?hl=en)、[比较词与主题](https://support.google.com/trends/answer/4359550?hl=en)、[CSV导出](https://support.google.com/trends/answer/4365538?hl=en)、[官方API及尺度](https://developers.google.com/search/apis/trends)、[百度指数官方帮助](https://index.baidu.com/Helper/?tpl=help)。来源开放情况以后仍需按当时页面核对，不把这次检查写成永久可用承诺。

Topic与搜索词覆盖范围不同，词的语言和歧义也会影响结果。类别可以帮助消歧。保存选项，不从界面语言推断用户想比较的市场，也不写死网页每次允许多少比较项。

Google的0可以表示低搜索量而非无人搜索，低量孤立尖峰也可能是噪声。全0序列在本策略中保守记为`insufficient_volume`；`<1`等删失值不擅自改成0。不要把相对指数解释成绝对搜索次数或用户比例。[数据FAQ](https://support.google.com/trends/answer/4365533?hl=en)

## 三个输出，分别解释

- **社区关注**：同平台/主题/帖子年龄下的讨论与互动；有有效基线才计算分位。不同平台计数不能相加，GitHub累计Star不代表本周热度。
- **搜索兴趣**：所选查询在明确地域、时段内的需求信号。必须能说明与当前事件的关系；否则只作背景。
- **个人阅读优先级**：以上两项结合证据、时效、历史增量和个人目标，回答先读什么。它不是事实置信概率或个人掌握度。

趋势曲线属于[按需展示](search-trend-display.md)：只在用户要求时展开。真实序列不可用时展示具体状态，不默认填充模拟数据。形式样例需用户明确要求，并与正式报告、排序数据隔离。

核验是入榜门槛：一手材料、时间和主张要能互相支持；计划按计划写，未核验线索单列。官方、X、仓库重复传播合并为同一事件。完整报告按知识树组织，事件只有一个主归属，其余节点引用；分支内按优先级排序。

## v1.1 的默认算法

```text
P = 100 × (0.20 S + 0.15 T + 0.075 C + 0.075 E + 0.20 N + 0.30 R)
```

S/C/N/R为0—1量规值；T和E由复算器计算。将v1的社区关注15%拆为社区7.5%和搜索7.5%，保持关注信号总预算15%，减少同一营销传播在两个渠道重复放大的影响。

- **S 来源证据**：0不可追溯，0.25仅有二手线索，0.5已核对边界明确的一手主张，0.75另有代码、条件或步骤可检查，1有针对相同主张的独立复现。S低于0.5不进入正式榜；名气不自动加分。
- **T 时效**：`2^(-日差/7)`。新品用发布日，案例用原始披露日并注明实践可能更早；检索、转载或格式更新不刷新时间。分组版本先确定原子事件或明确聚合口径，不取最后一条的时间替整组旧内容“变新”。
- **C 社区关注**：已有合格的同口径样本分位；没有基线则null。Agent负责核验原始互动、样本选择与采集时间，复算器不自动生成社区基线。
- **E 搜索兴趣**：这版复算器支持`google_trends`的`web_0_100`序列，同批相同口径的完整点取`mean(values)/100`。不同批次/市场/时段、缺点或未完成序列不能混算；API与百度原始尺度不进入此计算。数值不表示绝对需求量。
- **N 历史增量**：0重复，0.25补出处/少量说明，0.5新增细节或边界，0.75新能力/方法/实质证据，1有据改变核心判断。保留对照的历史记录；档案首次收录不等于行业首创。
- **R 个人相关度**：`0.5×目标匹配 + 0.3×可采取行动 + 0.2×知识连接价值`，子项取0/0.5/1并解释。U表示未校准，不表示不会或应被扣分。

搜索增速可另作解释；低基数、零分母或未完成周期不算“爆发倍数”，这版不再额外加入增长加分。重要反例、低热度专业材料仍可凭证据、增量和相关度获得高优先级。

### 缺失与可比性

记录原始状态：`ok / insufficient_volume / auth_required / not_configured / rate_limited / unavailable / not_comparable / ambiguous_query`。其他明确失败状态也保留。只有数据和口径均有效的`ok`才参与E；“可访问页面”和“拿到有效序列”不同。

C或E缺失时内部用0.5占位，输出对应热度仍为null，不显示虚构的50分。设缺失维度集合为M：

```text
P_min = 所有已知维度的加权贡献
P_max = P_min + 100 × sum(缺失维度权重)
P_mid = (P_min + P_max) / 2
```

仅E缺失时范围宽7.5分，C/E均缺失时宽15分。这个范围只描述缺失敏感性，不是统计置信区间，也没有包含人工S/N/R的不确定性。显示整数，差距小于5分视作近似同档；精确同分时按event_id稳定排列，名次先后不代表实质优劣。

多个网页比较批次不能仅靠相同日期拼在一起。若候选超过单次比较能力，可分组展示搜索兴趣，但不跨组生成全局E；目前复算器遇到不一致的有效批次会把这些E都降为`not_comparable`，其余维度继续排序。未来有经验证的锚点校准、API或多引擎归一化时另建策略版本并保留过程，不在此版隐含执行。

## 可复算输入

`scripts/rank_news.py`只处理已整理的输入，不访问网络、账户或个人档案。Agent从原始页面/CSV核对时间点和完成状态后整理JSON；保留工作数据的出处，不能根据印象填写序列。

新采集的搜索记录使用`data_kind: "observed"`标记真实观测。用户明确要求的形式演示使用`data_kind: "simulated"`，只保存在演示上下文。复算器对显式模拟记录输出`simulated_data`和未知E，即使其`status`误填为`ok`也不计入搜索分；旧记录未提供该字段时继续按既有核验契约处理。字段标记不能替代Agent对来源真实性的核验。

下面是**虚构结构示例**，不是实际产品搜索数据，因此标记为`simulated`，运行后E保持未知。用于正式数据时，必须取得真实序列及其来源并标记为`observed`。主榜事件的来源与S/N/R评分理由应同时保存在研究上下文。

```json
{
  "as_of": "2026-11-06",
  "search_window": {"start": "2026-10-30", "end": "2026-11-05"},
  "items": [
    {
      "event_id": "example-release",
      "primary_node_id": "model-access",
      "published_at": "2026-11-04",
      "verified": true,
      "scores": {"S": 0.75, "C": null, "N": 0.75, "R": 0.9},
      "search_interest": {
        "status": "ok",
        "data_kind": "simulated",
        "provider": "google_trends",
        "scale": "web_0_100",
        "comparison_id": "example-shared-export",
        "query": "Example Model 1",
        "query_kind": "term",
        "geo": "worldwide",
        "window_start": "2026-10-30",
        "window_end": "2026-11-05",
        "timezone": "Asia/Shanghai",
        "category": "all",
        "search_property": "web",
        "resolution": "daily",
        "source_url": "https://trends.google.com/trends/explore",
        "collected_at": "2026-11-06T09:00:00+08:00",
        "attribution": "exact_event",
        "is_partial": false,
        "values": [20, 25, 30, 40, 50, 60, 55]
      }
    }
  ]
}
```

用原始导出或查询批次标识`comparison_id`，不能为独立请求捏造相同ID。`attribution=exact_event`是核验后的事件关联判断；广义品牌、缩写歧义用`broad`等背景标记，不进入该事件E。同批有效记录的地域、窗口、时区、类别、类型、词/主题、分辨率和序列长度应一致；Agent还需核查实际时间点对齐，代码不会证明填写的元数据真实。

`search_window`省略时默认截至`as_of`的7个自然日；当天尚未完成时显式选一个已完成窗口，或保留部分状态使E未知。完整日窗口要求采集时刻已进入结束日之后，daily序列必须覆盖每一天；其他分辨率的时间点对齐仍由Agent核对。不要把更早的曲线标成本期搜索热度。`search_interest`为null或缺失表示无数据；不要提交`values:[0]`来代替访问失败。

运行并保留版本化结果：

```bash
python3 scripts/rank_news.py ranking-input.json
python3 scripts/rank_news.py ranking-input.json --output ranking-results.json
```

### 写入成长档案

本次`context/ranking-input.json`与`ranking-results.json`保留策略版本、截点、来源状态、序列/口径、分项贡献和缺失范围。原始导出放`.cognirings/research/`并保留来源引用；报告显示搜索与社区信号的不同含义，不发布登录数据或个人查询内容。详细位置遵循[档案契约](archive-contract.md)。

权重和归一化变更只用于新计算；已有v1报告保持当时结果。若用户要重算历史，应形成新的带版本结果并说明变化。排序改善不构成理解等级提升。
